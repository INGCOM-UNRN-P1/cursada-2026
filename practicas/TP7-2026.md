## Decisiones de Arquitectura y Diseño

> [!NOTE] **Especificación Algorítmica en `docs/`**:
> Consultá la guía detallada [docs/algoritmos.md](docs/algoritmos.md) para el detalle matemático y conceptual de los algoritmos de rasterización (Bresenham, punto medio), normalización min-max, paletas de calor e inundación recursiva (flood-fill).

### Representación Contigua de Matrices en Heap

En `libmatrices` y en el tablero de `buscaminas_t`, se aplica la estrategia canónica de doble puntero indexable sobre bloque contiguo:

```c
/* Un único bloque contiguo en heap para todos los elementos */
m->datos = malloc(filas * columnas * sizeof(tipo_t));

/* Arreglo de punteros donde cada fila apunta al inicio de su tramo */
m->filas = malloc(filas * sizeof(tipo_t *));
for (size_t i = 0; i < filas; i++)
{
    m->filas[i] = m->datos + (i * columnas);
}
```

**Ventajas clave**:
- Permite la sintaxis natural de doble indexación `m->filas[i][j]`.
- Garantiza localidad espacial estricta (aprovechamiento óptimo de líneas de caché L1/L2/L3).
- La liberación de memoria se realiza en tiempo constante mediante dos llamadas a `free` (`free(m->filas)` y `free(m->datos)`), evitando fragmentación del heap.

### Encapsulamiento Estricto mediante Tipos Incompletos (TDA Opaco)

Siguiendo el estándar pedagógico de P1:
- El archivo `.h` declara únicamente el tipo incompleto:
  ```c
  typedef struct nombre_tda nombre_tda_t;
  ```
- La definición concreta de `struct nombre_tda { ... };` reside exclusivamente en el archivo de implementación `.c`.
- Los clientes y suites de prueba interactúan con el TDA única y exclusivamente a través de sus primitivas públicas, preservando los invariantes de representación.

## Consignas de los Ejercicios

### Ejercicio 1: Visualizador de Matrices Numéricas a BMP (`matriz_grafica_t`)

El objetivo es construir un TDA opaco capaz de representar visualmente los valores escalares de una matriz dinámica (`matriz_t`) en una imagen BMP de 24 bits.

#### Responsabilidades funcionales:
1. `matriz_grafica_crear(const matriz_t *matriz, int tam_celda)`: Asocia una matriz existente y define el factor de escala (lado en píxeles de cada celda).
2. `matriz_grafica_configurar_paleta(matriz_grafica_t *mg, paleta_color_t paleta)`:
   - `PALETA_ESCALA_GRISES`: Normaliza el rango `[min, max]` de la matriz a niveles de intensidad de 0 (negro) a 255 (blanco).
   - `PALETA_CALOR`: Gradiente térmico continuo de 5 paradas: Azul (frío/mínimo) $\rightarrow$ Cian $\rightarrow$ Verde $\rightarrow$ Amarillo $\rightarrow$ Rojo (caliente/máximo).
3. `matriz_grafica_configurar_borde(matriz_grafica_t *mg, bool dibujar_borde, color_t color_borde)`: Activa o desactiva la grilla separadora entre celdas.
4. `matriz_grafica_renderizar(const matriz_grafica_t *mg)`: Retorna un nuevo `bmp_t *` con la imagen generada.
5. `matriz_grafica_exportar_bmp(const matriz_grafica_t *mg, const char *ruta)`: Renderiza y persiste la imagen directamente a disco.

### Ejercicio 2: Primitivas Gráficas Vectoriales sobre BMP (`lienzo_t`)

La biblioteca `libbitmap` expone manipulación a nivel de píxel individual (`bmp_set_pixel`). Este ejercicio extiende esa base construyendo un TDA opaco de dibujo vectorial de alto nivel.

#### Primitivas a implementar:
1. `lienzo_crear(int ancho, int alto, color_t color_fondo)` y `lienzo_destruir(lienzo_t *lienzo)`.
2. `lienzo_dibujar_pixel(lienzo_t *lienzo, coordenada_t punto, color_t color)`: Validación de límites estricta.
3. `lienzo_dibujar_linea(lienzo_t *lienzo, coordenada_t p1, coordenada_t p2, color_t color)`: Implementación del **Algoritmo de Bresenham** para trazar segmentos en cualquier octante con aritmética entera pura.
4. `lienzo_dibujar_rectangulo(lienzo_t *lienzo, coordenada_t p1, coordenada_t p2, color_t color, bool rellenar)`: Soporte para perímetro o relleno sólido.
5. `lienzo_dibujar_circulo(lienzo_t *lienzo, coordenada_t centro, int radio, color_t color, bool rellenar)`: Implementación del **Algoritmo de Punto Medio (Bresenham para circunferencias)** aprovechando la simetría de 8 octantes, con relleno por tramos horizontales.
6. `lienzo_limpiar(lienzo_t *lienzo, color_t color_fondo)` y `lienzo_guardar_bmp(const lienzo_t *lienzo, const char *ruta)`.

### Ejercicio 3: Tablero de Buscaminas con Matriz de Structs (`buscaminas_t`) (A diseñar íntegramente)

Desarrollo de un juego completo modelado mediante un TDA opaco cuya estructura interna es una matriz dinámica contigua de estructuras `celda_t`.

> [!IMPORTANT] **Diseño de Interfaz a Cargo del Estudiante**:
> En este ejercicio **no se proveen prototipos prefijados**. El estudiante debe diseñar la arquitectura del TDA en `buscaminas.h`: decidir nombres de funciones, tipos de datos, parámetros (por valor o referencia), const-correctness y documentación Doxygen.

```c
typedef struct
{
    bool tiene_mina;        /* Indica si la celda oculta una mina */
    bool revelada;          /* true si ya fue descubierta por el jugador */
    bool marcada;           /* true si tiene bandera preventiva */
    int minas_adyacentes;   /* Conteo de minas en las 8 celdas vecinas (0..8) */
} celda_t;
```

#### Consideración de Diseño: Coordenadas como TDA
Se recomienda modelar las coordenadas del tablero como un Tipo de Dato Abstracto (`coordenada_t`, ya sea reutilizando el tipo de `bitmap.h` o definiendo uno propio). De esta forma, las operaciones del juego reciben posiciones encapsuladas (evitando inversiones de parámetros `fila/columna`).

#### Requerimientos que debe satisfacer la API diseñada:
1. **Ciclo de vida**: Inicialización aleatoria y constructores deterministas (imprescindibles para testing en `prueba.c`), junto con destrucción limpia de memoria en bloque contiguo.
2. **Inspección**: Consultas de dimensiones, cantidad de minas y estado de celdas por copia.
3. **Acciones de juego**: Marcado de banderas y revelación con **apertura en cascada recursiva (flood-fill)** ante celdas con 0 minas vecinas.
4. **Estado de partida**: Consulta de fin de juego (victoria vs. derrota por detonación).
5. **Integración con Bitmap**: Renderizado y exportación del estado visual del tablero a archivo BMP con `libbitmap`.
